**Rules applied:**
- Newest mtime wins on path collisions
- SHA-256 hash equality → single copy kept
- Files >100 MB excluded (LLM weights, model blobs, Ollama sha256-* files, big zips)
- Excluded dirs: `.git`, `.venv`, `venv`, `env`, `node_modules`, `__pycache__`, `.pytest_cache`, `.mypy_cache`, `.ruff_cache`, `.tox`, `.cache`, `dist`, `build`, `*.egg-info`, `blobs`, `.next`, `.nuxt`, `target`, `bin`, `obj`, `.idea`

**Git:** local `main` branch, single initial commit, **no remote** (per user choice).

## Re-merging (resumable)

The merge engine is idempotent. Re-run `LAUNCH_MERGE.cmd` whenever you update any source folder. It will:
1. Re-scan all sources
2. Skip files whose hash already matches destination
3. Overwrite only files whose source mtime is newer
4. Append new files

## Rollback

```powershell
# Nuke everything and start over (sources untouched)
Remove-Item -Recurse -Force C:\Users\User\JARVIS_SINGULARITY
# Then re-run LAUNCH_MERGE.cmd
```

## Re-source from singularity

If you want any source folder to be a copy of singularity (reverse direction):
```powershell

```
